Sprint 0 decision record · 16 Oct 2026

Product brief: PR #184 — student workflow requirements (draft). Board status: PROPOSED · READY FOR OWNER REVIEW. Owner approval is pending; do not use this board as permission to begin production UI implementation.

Recommended direction: use a calm, mostly light neutral workspace with one restrained accent, fixed and understandable navigation, a strong page title and primary action, compact but readable information density, real task/run states and responsive layouts. The AI workspace should make the composer, current conversation, run/tool status, approvals and saved artifacts understandable as one workflow. Use a denser canvas only for workflow/diagram editing while retaining shared semantic tokens.

Adopt: recognizable navigation, visible source/context, keyboard-ready controls, clear task priority/deadline, truthful status, intentional empty/error/unauthorized states. Reject: invented KPIs, decorative graphs, huge hero panels that displace the task, gradients everywhere, copied branding, inert controls and separate per-page token systems.

Owner decision: PENDING. This is a research recommendation, not approval. A0 checks product fit; A3 checks shared design tokens; owner chooses or requests changes before production UI work.

Design synthesis — proposed direction to review

Do: calm neutral technical workspace, high contrast, one brand accent, semantic status colors, compact readable task density, stable sidebar/topbar, shared icon family, genuine states, responsive and keyboard support.

Do not: reproduce references literally; mix unrelated gradients; invent KPI charts; use mock metrics as live values; leave inert controls; or introduce a unique design language on every page. Canvas/diagram screens may use denser/darker work surfaces while retaining the same semantic tokens.
